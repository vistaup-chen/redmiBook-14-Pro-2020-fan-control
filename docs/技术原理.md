# 技术原理与实测记录

> 机器：RedmiBook 14 增强版 2020（TIMI TM1901，BIOS RMRCM400P0100，i7-10510U + MX250）
> 以下所有寄存器与数据均为 2026-10-29 凌晨在本机实测，非理论推测。

## 1. 风扇为什么吵 —— 根因

EC（嵌入式控制器）的**自动风扇曲线过于激进**：

| 状态 | EC 自动模式 | 本方案静音模式 |
|---|---|---|
| 52-54℃ 怠速 | 占空比 0x86（≈59% 档，风扇持续中速转） | 占空比 0xC8（**风扇停转**） |
| 55℃ | 略升 | 才开始以最低档（35%）启动 |
| 58-60℃ | 更响 | 35-55% 轻柔档 |

原「节能」电源方案已把 CPU 限到 60% 状态+禁用加速，但风扇依然吵 —— 证明噪音与性能设置无关，**必须改写 EC 才能安静**。

## 2. EC 寄存器地图（实测）

通过 ACPI EC 端口 0x62/0x66（RD_EC/WR_EC 协议）访问 EC RAM：

| 寄存器 | 作用 | 实测行为 |
|---|---|---|
| **0x93 (147)** | 风扇控制模式 | 写 `0x1C`=手动，写 `0x04`=自动。**必须先写它再写占空比**，否则 EC 忽略外部写入 |
| **0x94 (148)** | 风扇占空比（写入） | **反向映射：值越小转速越高**。实测范围：`0x77`(119)=全速，`0xA4`(164)≈最低可转档，`≥0xC8`(200)≈停转，`0xFF`=停转 |
| **0x95 (149)** | 占空比回读 | ≈0x94±2~5（EC 校准值），可作为写入是否生效的验证 |
| 0xA8 (168) | CPU 温度（℃） | 与实际负载温度一致（53-60℃ 区间跟踪良好） |
| 0xA9/0xAA/0xAB | 其他温度传感器 | 41-47℃ / 42-44℃ / 与 0xA8 近似 |
| 0xE0-0xE3 | 恒定值 0x0B82 | 非转速计数（实验排除） |
| 未发现 | 16 位转速计数器 | EC RAM bank0 中不存在（NBFC 因此按百分比显示） |

四个阶段的完整转储对比见 [ec-dump-experiments.md](ec-dump-experiments.md)。

### 实测关键结论
1. 写 `0x93=0x1C` 后 EC **持续接受** 0x94 写入（90 秒观察期不回写覆盖）。
2. 写 `0x94≥0xC8` 后温度 54-56℃ 稳定（轻载），风扇停转。
3. 写回 `0x93=0x04` 后 EC **立即恢复自动控制**（回读值从外部值过渡回自动值）。
4. **强杀 NBFC 服务进程后 EC 停留在手动模式不会自行还原** —— 但 Windows 服务管理器会自动重启服务（NBFC 安装时配置了恢复选项），重启后 1 秒内重新接管。极端兜底用 `scripts\紧急恢复风扇.bat`（写回 0x93=0x04）。

## 3. CPU 功耗墙（MSR，i7-10510U）

通过 NBFC 自带的 OpenHardwareMonitorLib.dll（Ring0 类）读写 MSR（WinRing0_1_2_0 驱动）：

| MSR | 值 | 解码 |
|---|---|---|
| 0x610 PKG_POWER_LIMIT | `0x0042819800DD80C8` | **PL1=25W**（使能+clamp，时间窗≈28s）、**PL2≈51W**（使能）、**未锁定（bit63=0，可写）** |
| 0x606 RAPL_POWER_UNIT | `0x000A0E03` | 功率单位 1/8W、时间单位 1/1024s |
| 0xCE PLATFORM_INFO | `0x4043DF1011700` | 最大非睿频倍频 23（2.3GHz） |
| 0x1AD TURBO_RATIO_LIMIT | `0x2B2B3031` | 睿频：1核4.9GHz / 2核4.8GHz / 3-4核4.3GHz |
| 0x770 PM_ENABLE | 1 | HWP（Speed Shift）已启用 |
| 0x601 VR_CURRENT_CONFIG | 0x238 | PL4/电流墙 ≈ 568×0.25A？未深究 |
| 0x614 PKG_POWER_INFO | 0x78 | Max Power=120×0.125=15W（标称 TDP 参考） |

**极限模式的功耗墙解锁**：把 PL1 字段（bits 14:0）从 200 改为 224（28W），保持使能/clamp/时间窗与 PL2 全部原样 —— 写入并回读确认成功（`0x0042819800DD80C8 → 0x0042819800DD80E0`）。退出极限模式自动还原 25W。

> 注：MSR 改写重启后失效，属于「每次进极限模式时重新施加」的设计，天然可逆。

| 方案 GUID（前缀 9a10e4a1-1111-4b7a-8c0d-） | 最大处理器状态 | EPP | 加速模式 |
|---|---|---|---|

## 5. 软件栈

- **NBFC 1.6.3**（hirschmann）：唯一常驻组件。服务 `NbfcService`（AUTO_START），内核驱动 `WinRing0_1_2_0`（运行时加载，无需重启机器）。
  - 配置目录 `C:\Program Files (x86)\NoteBook FanControl\Configs\`，本机专属配置 4 份（源文件在本仓库 `nbfc-configs\`）。
  - 持久化设置 `C:\ProgramData\NbfcService\NbfcServiceSettings.xml`（SelectedConfig + Autostart=true）→ **重启后自动恢复上次的模式**。
  - 自带 `ec-probe.exe`（EC dump/read/write/monitor）与 `nbfc.exe`（CLI）。
- **LibreHardwareMonitor 0.9.6**（`tools\LHM\`）：便携版，仅作传感器交叉验证（本机未装 PawnIO，LHM 的 EC/CPU 内核读数不可用，GPU/电池/内存可用）。非必需组件。
- 360 安全卫士在本机全程运行：NBFC 驱动安装与 EC 写入未被拦截；但 360 会**静默隔离无签名的自编译 MSR 工具**（msr.exe 曾被清掉），因此最终方案用 NBFC 自带库反射调用，稳定且免杀。

## 6. 已知限制

1. 风扇转速无 RPM 直读（EC 未暴露计数器），NBFC 显示的百分比为占空比映射。
2. 极限模式的满载表现未做长时间满载测试（遵守不干扰其他任务的约束），28W PL1 的稳定性基于社区同机型数据（IT之家评测该机短时 25W+），如遇极少数不稳定场景请用「恢复默认」。
3. BIOS 更新可能改变 EC 寄存器映射（RMRCM400P0100 已验证；若将来刷 BIOS 需重新验证 0x93/0x94）。
4. MSR 功耗墙改动重启后自然失效；电源方案与 NBFC 配置则持久保存。
